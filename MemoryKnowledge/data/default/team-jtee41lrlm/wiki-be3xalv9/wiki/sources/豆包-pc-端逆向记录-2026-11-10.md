# 摘要

本文是一次针对 [[豆包 PC 客户端]] **2.35.8**（channel 1001，Electron / Chromium 147.0.7727.149）安装目录 `C:\Users\Administrator\AppData\Local\Doubao` 的逆向分析记录。

核心判断：豆包 PC 端**不是纯网页壳**，而是 [[混合原生 + Electron 壳架构]]——表面是 Electron 网页外壳，重逻辑落在若干原生 DLL 与随包分发的 **可读 Python 源码**中。正是这批 `.py` 文件让工具集可被审计，构成了本次逆向的主入口。

# 主要发现

## 1. 组件构成

安装目录下存在 7 个原生 DLL 与 Python 包资源：

| 组件 | 体积 | 作用 |
|---|---|---|
| `Doubao.dll` | 317 MB | 主逻辑 + 内置 JS bundle |
| `liblark.dll` | 167 MB | 飞书同源内核 |
| `cccreator.dll` | 85 MB | 创作 / 画布能力 |
| `mcp_helper.dll` | 16 MB | MCP 协议客户端（见 [[MCP Helper DLL]]） |
| `agent_infra.dll` | 10 MB | Agent 基础设施 |
| `sdks\aha_cua\aha_cua.dll` | — | Computer Use Agent SDK（见 [[Aha CUA DLL]]） |
| `task-mode-resource\python-packages` | — | 纯 Python 源码的 Agent 工具集 |

## 2. 工具集一：浏览器操作（50 个）

源码位于 `task-mode-resource\python-packages\aha_browser_use\`，路由表 `_routes.py` 中**硬断言必须正好 50 个工具**。详见 [[Aha Browser Use 浏览器工具集]]。

设计要点：
- 按 [[工具路由分层]] 的 6 类 `Route` 枚举调度（AHA_BUA 24 / NATIVE_COMPAT 9 / COMPOSITE 9 / SEED_DIRECT 5 / CDP_COMPAT 3 / LOCAL 2）。
- 固定 [[工具协议错误码]]（`BU_REF_STALE`、`BU_SELECT_AMBIGUOUS`、`BU_DOWNLOAD_BLOCKED` 等），构成契约面。
- 交互范式是 [[snapshot→ref→act 协议]]：先 `snapshot` 取带编号节点树，再按 ref 点击，而非坐标点击；与 [[Playwright MCP]] 同类方案思路一致。

## 3. 工具集二：Windows 桌面操作（17 个）

源码位于 `gac_runtime\modules\computer_use_windows.py`（协议版本 1，模块 ID 2），共 17 个工具，另有 7 个服务层模块（`app` / `clipboard` / `desktop` / `keyboard` / `mouse` / `screenshot` / `wait`）。详见 [[Computer Use Windows 桌面工具集]] 与 [[桌面 Agent 最小完备工具集]]。

特点：截图上限 128 MB、单帧响应上限 129 MB、传输超时 500 秒（为长任务设计）；`switch_desktop` 可切 Windows 虚拟桌面；`key_down` / `key_up` 可分离以支持组合键长按。

## 4. 技能 / 模式

| 模式 | 落点 | 能力 |
|---|---|---|
| [[任务模式 runtime-bundle]] | `task-mode-resource\runtime-bundle` | 后台长任务，带 Python 运行时 |
| [[编程模式（coding）]] | `User Data\coding` | 起 [[子 agent]] 在沙箱里写代码、直接改文件 |
| [[沙箱运行时]] | `User Data\sandbox_runtime`（519 MB） | 内置 Node + Python，带 npm / pip 缓存 |

[[Seed 能力包族]]（`seed_browser_use` / `seed_computer_use` / `seed_computer_use_ax`）是底层能力包，其中 `_ax` 走 [[Windows UI Automation]] 无障碍树，即 [[无障碍树 vs 像素识别]] 中的 AX 路线。

## 5. 执行实证

`User Data\coding\snapshot\` 下 5 条 [[执行快照目录]] 记录全部集中在 2026-09-26 14:06–14:14，均为 `agentType=sub_agent`、`firstToolName=Write`，直接写入 `AI\02_研究资料\骑砍2模组\` 等任意路径，行数 229–391 不等。元数据（`agentId=s_xxxx`、`sandboxId`、`addedLines`、`changeType`）**仅本地留存、不做清理**，即 [[本地执行痕迹]]。

结论：编程模式能在本机起 [[子 agent]]，用 Write 工具直接落盘到任意路径——这直接支撑了 [[本地任意目录读写权限模型]] 这一最关键的安全判断。

# 可复用的工程结论

1. **做浏览器 Agent**：照 `aha_browser_use` 的分层抄——50 个工具分 6 类路由，核心是 snapshot→ref→act 三步，别用坐标点击。
2. **做桌面 Agent**：`computer_use_windows` 的 17 个工具即最小完备集，重点是 `screenshot` + `click/hover/drag/scroll` + `type/hotkey` + `wait` + `clipboard`。
3. **做长任务**：必须有沙箱（Node + Python），否则模型写不出可执行的中间产物（见 [[沙箱内子 agent 长任务模式]]）。
4. **安全上要知道**：安装豆包等于部署一个可读写任意目录的远程 Agent，执行记录仅本地留存，上报可见性未知。
